# コントリビューションガイド

コントリビューションを歓迎します！みなさんの協力に感謝します。
以下の方法でプロジェクトに参加できます。

- Issueの作成 - 新機能の提案やバグ報告。
- ミドルウェア・ライブラリの開発 - Honoのエコシステムを広げる。
- 発信・共有 - ブログやXなどで知見や感想を共有する。
- スポンサー - GitHub Sponsors（[@yusukebe](https://github.com/sponsors/yusukebe) および [@usualoma](https://github.com/sponsors/usualoma)）を通じてメンテナーを支援する。
- アプリケーションの開発 - Honoを使ってアプリケーションを作る。

補足:
このプロジェクトは Yusuke Wada（[@yusukebe](https://github.com/yusukebe)）が趣味として始めたものです。
純粋に楽しみとしてスタートしたプロジェクトであり、そのスタンスは現在も基本的に変わっていません。
自分が書きたいようにコードを書きたいと考えています。
そのため、素晴らしいアイデアを提案していただいても、方針に合わない場合は採用されないことがあります。

とはいえ、心配しないでください！
Honoは十分にテストされ、コントリビューターによって磨かれ、多くの開発者に使われています。これからもHonoをクールでホット、美しく、そして超高速なフレームワークにするために全力を尽くします。

## AI利用ポリシー

コントリビューションにあたってAIを利用しても構いませんが、メンテナーの時間を奪ったり、メンテナーの作業に負担をかけたりすることは絶対に避けてください。

この方針を守るため、実際にAIが使われたかどうかにかかわらず、メンテナーの判断で予告なくIssueをクローズし、アカウントをブロックする場合があります。

## プルリクエストではなくIssueで報告してください

プルリクエストの作成はメンテナーのみに制限されています。バグを見つけた場合や変更を提案したい場合は、プルリクエストではなくIssueを作成してください。最小限の再現コードを添えた明確なIssueの方が、プルリクエストよりも助けになります。

## ローカル開発

`honojs/hono` プロジェクトでは、パッケージマネージャーとして [pnpm](https://pnpm.io/) を使用し、ビルドおよび一部のテストの実行に [Bun](https://bun.sh/) を使用しています。開発時は両方をインストールしてください。

```bash
git clone git@github.com:honojs/hono.git && cd hono && pnpm install --frozen-lockfile
```
